# Bounded task packets

Give each child one objective, the relevant requirements, source/context, owned paths for edits, constraints, dependencies and a concise expected result. Include the user's execution boundary. For mechanic, supply the exact edit recipe. For explicit-only specialists, quote the user's request authorizing that activity; a host-created task label is not authorization.

Use existing chat results and readable diffs directly. Do not require baseline hashes, output digests, artifact signatures, logs, receipts or a separate packet file. Do not forward unrelated conversation history.

Children do only their packet and never delegate. Writers modify only their assigned paths. Reviewers, researchers and planners stay read-only. A review finding is not permission for the reviewer to fix code. Existing files and user edits outside the task remain untouched.

Return the actual change or answer with useful paths, concrete findings and any specific blocker. No ceremonial evidence bundle or duplicate check. If commands were explicitly requested, report the command and actual result in chat; do not create logs by default.
